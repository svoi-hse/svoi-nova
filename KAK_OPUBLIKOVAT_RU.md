# Как опубликовать «Свои» только через GitHub

Инструкция рассчитана на человека, который впервые пользуется GitHub. Код менять, устанавливать программы и открывать терминал не требуется.

## Что получится

После этих шагов появится публичная ссылка, которую можно отправить друзьям. Сайт откроется на компьютерах и смартфонах. Его оформление, демонстрация OneLove, переход «анкеты → чат», просмотр демо-профилей и редактор анкеты будут интерактивными.

**Важно:** это публичное демо, не настоящая многопользовательская система знакомств. У всех посетителей будет своё отдельное состояние в браузере; сообщения другим людям не отправятся. GitHub Pages не может запускать сервер Python или общую базу данных.

## 1. Распакуй архив

Скачай `Svoi_GitHub_Pages_Demo.zip` и распакуй. Внутри появится папка с `index.html` и папкой `assets`. Именно их нужно загрузить в репозиторий.

## 2. Создай репозиторий

Перейди на `https://github.com/` и войди в аккаунт. В правом верхнем углу нажми `+`, затем `New repository` (Новый репозиторий).

- Repository name: `svoi-nova`.
- Visibility: `Public` (публичный), чтобы GitHub Pages работал на бесплатном аккаунте.
- Остальные настройки оставь по умолчанию.
- Нажми `Create repository`.

Если GitHub предложит добавить README при создании, это не обязательно: наш README уже в папке.

## 3. Загрузи файлы

На странице нового репозитория выбери `Add file → Upload files`. Если репозиторий пустой, можно нажать `uploading an existing file`.

Открой распакованную папку на Mac. Выдели **всё внутри неё**, а не саму папку. Перетащи выделенное в окно загрузки GitHub. Файл `index.html` после загрузки должен быть **в корне репозитория**, а папка `assets` должна находиться рядом с ним.

Важно: не отправляй ZIP как один файл. GitHub Pages не распаковывает его для запуска сайта. На Mac скрытый файл `.nojekyll` можно не выбирать: для работы этой сборки он необязателен.

После завершения загрузки нажми `Commit changes` (или `Commit directly to the main branch`).

## 4. Включи GitHub Pages

Открой верхнюю вкладку `Settings`, затем слева раздел `Pages`.

В разделе `Build and deployment` выбери:

- `Source`: **Deploy from a branch**.
- `Branch`: **main**.
- `Folder`: **/(root)**.
- Нажми `Save`.

GitHub опубликует файлы автоматически. На той же странице появится ссылка `Visit site`. Иногда обновление занимает несколько минут.

## 5. Проверь адрес

Если твой GitHub-ник, например, `student123`, то при репозитории `svoi-nova` ссылка будет:

`https://student123.github.io/svoi-nova/`

Открой её на телефоне. Сначала появится главный экран, затем можно открыть OneLove и протестировать выбор одной анкеты и чат.

## 6. Обновление сайта

Для следующей версии снова зайди в этот репозиторий, выбери `Add file → Upload files`, перетащи **содержимое новой папки** и подтверди замену совпадающих файлов. Нажми `Commit changes`. GitHub Pages автоматически опубликует изменения.

## Если не получилось

**Открывается README вместо сайта или ошибка 404:** проверь, что `index.html` лежит в корне репозитория, а в Settings → Pages выбран `main / (root)`.

**Сайт без оформления:** проверь, что папка `assets` загружена целиком вместе со вложенными файлами, а не пустая.

**После обновления старая версия:** обнови страницу и проверь, что загрузка завершилась через Commit changes. GitHub Pages иногда обновляет сайт не мгновенно.

**У друга не видны мои сообщения:** так и задумано для демо. Здесь нет настоящей базы или доставки сообщений.

## Что понадобится для настоящего запуска

Один GitHub Pages недостаточен. Необходим хотя бы один внешний сервис, который выполняет серверный код и хранит данные всех пользователей. В проекте NOVA 2.0 подготовлена более полная Python-версия для этой цели. Публичные аккаунты и чаты нельзя безопасно имитировать через общий GitHub-репозиторий или открытые токены в JavaScript.
